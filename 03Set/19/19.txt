1. It is appropriate to use an int-type parameter when the arguement type is cheap to copy and the function does not need to modify the original variable. 
In the code example this is isllustrated because num is small and copying it is as cheap as using a reference and square does not need to change the caller's orginal variable.

    int square(int num)
    {
        return num * num;
    }

2. It is appropriate to define a std::string value parameter when the function needs its own independent, modifiable copy of the string.
In the code example this is illustrated because the constructor must own a copy of the string to store as a member. 

    class Person
    {
        std::string name;

        public:
            Person(std::string name)
            :
                name(std::move(name))
            {}
    };

3. There are no situations where it is better to define a const reference to an int-type parameter because of the cheap cost to copy an int.

4. It is appropriate to define a const reference to a std::string parameter when the function only needs to read the string's content and doesn't need an independent copy or need to store it. 
In the code example this is illustrated because printLength only inspects str and passing it by const reference avoids duplicating the whole strings character data just to read its length

    void printLength(const std::string &str)
    {
        std::cout << str.length << '\n';
    }

5. It is appropriate to define a non-const reference to an int-type parameter when the function needs to modify the caller's variable directly.
In the code example this is illustrated because increment is meant to change the caller's actual variable and if num was passed by value it would only alter a local copy.

    void increment(int &num)
    {
        ++num;
    }

6. It is appropriate to define a non-const reference to a std::string parameter when the function needs to modify the caller's string in place and the modification needs to be visible to the caller after the call returns.
In the code example this is illustrated because str is mutated for the caller's benefit. 

    void appendExclamation(std::string &str)
    {
        s += '!';
    }

7. There are no situations where it is appropriate to define a const rvalue-reference to an int-type parameter because an rvalue-reference exists so a function can detect a temporary, but moving an int is identical to copying it.

8. There are no situations where it is appropriate to define a const rvalue-reference to a std::string parameter because the rvalue-reference only accepts temporaries but since it is a const it prevents you from stealing its resources. Along with this a normal reference can accept both lvalues and rvalues which is much more practical.

9. There are no situations where it is appropriate to define an rvalue-reference to an int-type parameter since it is just a copy, and therefore it would be more practical to pass by value instead.

10. It is appropriate to define an rvalue-reference to a std::string parameter when the function should capture, and be allowed to move from, a temporary or otherwise discardable string.
In the code example this is illustrated because the first constructor is selected when the caller passes a temporary, letting Person steal the temporary's buffer via std::move instead of copying its characters. The second constructer handles the case where the caller's string must be preserved so a real copy is made.

    class Person
    {
        std::string name;

        public:
            Person(std::string &&name)      :name(std::move(name)) {}
            Person(const std::string &name) :name(name)            {}
    };

11. It is appropriate to return an int-type parameter when the function computes or produces a new value that doesn't correspond to an already-existing object's storage.
In the code example this is illustrated because num1 + num2 is a brand-new temporary value with no storage elsewhere.

    int add(int num1, int num2)
    {
        return num1 + num2;
    }

12. It is appropriate to return a std::string value when the function constructs and returns a brand-new string with no pre-existing owner.
In the code example this is illustrated because the returned string is a new temporary produced inside the function and there is no existing object to return a reference to.

    std::string greet(const std::string &name)
    {
        return "Hello, " + name;
    }

13. It is appropriate to return a const reference to an int when the value being returned is a member that outlives the function call, the caller only needs read access, and you want to avoid a copy while preventing modification through the returned reference.
In the code example this is illustrated because count is a member that continues to exist after value() returns, so referring to it is safe. const stops the callers from changing count throught the reference they recieve

    class Counter
    {
        int cound = 0;

        public:
            const int &value() const { return count; }
    };

14. It is appropriate to return a const reference to a std::string when returning read-only access to an existing string member (or other long-lived string), avoiding the cost of copying its buffer while still preventing external modification.
In the code example this is illustrated because name can hold a sizeable amount of data and returning const string& avoids duplicating the data on every call, while const prevents callers from changing name through the reference.

    class Person
    {
        std::string name;

        public:
            const std::string &getName() const { return name; }
    };

15. It is appropriate to return a non-const reference to an int when the caller should be able to directrly modify an internal int throught the returned reference.
In the code example this is illustrated because at() gives direct, mutable access to data[indx]. The reference targets storage that persists beyond the call which makes it safe.

    class Array
    {
        int data[10];

        public:
            int &at(size_t idx) { return data[idx]; }
    };

16. It is appropriate to return a non-const reference to a std::string when the caller should be able to directly modify an internal string through the returned reference.
In the code example this is illustrated because the stored member is directly modified through the returned reference.

    class Person
    {
        std::string name;

        public:
            std::string &name_() { return name; }
    };

17. It is not appropriate to return a const rvalue-reference to an int becuase returning a reference to a local variable would be useless as when the function terminates the variable would not exist.

18. It is not appropriate to return a const rvalue-reference to a std::string as returning a reference to a local variable would be useless as when the function terminates the variable would not exist.

19. It is not appropriate to return an rvalue-reference to an int because the local variable would be discarded when the function terminates leaving the reference useless and returning an int by value is just as effecient.

20. It is appropriate to return an rvalue-reference to a std::string when calling a function on a temporary object signals that it's safe to move a member out of it, since the temporary is about to be destroyed anyway.
In the code example this is illustrated because Wrapper{} is a temporary that will be destroyed right after the full expression finishes, calling .extract() on it safely hands over data's buffer via move rather than copying it, since nothing will read data from the destroyed temporary afterward.

    class Wrapper
    {
        std::string data;

        public:
            std::string &&extract() &&
            {
                return std::move(data);
            }
    };
